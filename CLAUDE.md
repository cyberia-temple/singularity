This file provides Claude Code guidance for the Singularity repository. Keep it aligned with `AGENTS.md`, which is the cross-agent source of truth.

## Overview

**Singularity** is the Cyberia ecosystem monorepo. Cyberia is an EVM-compatible chain with chain ID `49406`, RPC `https://rpc.cyberia.church`, native token `CYBER`, explorer `https://explorer.cyberia.church`, bridge `https://bridge.cyberia.church`, site `https://cyberia.church`, DEX `https://swap.cyberia.church`, and CYBER.sol mint `E67WWiQY4s9SZbCyFVTh2CEjorEYbhuVJQUZb3Mbpump`.

## Safety Rules

- Do not print or commit secrets from `.env`, wallet keypair JSON files, cookies, bot tokens, private keys, or production Blockscout env files. Mention variable names only.
- Do not edit generated dependency/runtime folders unless explicitly requested: `node_modules/`, `vendor/`, `target/`, `build/`, `_site/`, `artifacts/`, `cache/`, `test-ledger/`, `logs/`, `linux/custom-root/`, `frontend/desktop/dist/`, `frontend/mobile/www/`, `frontend/extension/dist/`, and Blockscout data volumes under `services/blockscout/docker-compose/services/*-data/`.
- Prefer `rg --files` and scoped searches over broad `find` walks through runtime trees.
- Root `README.md` is user-facing and currently less complete than agent docs. Do not rely on stale root paths such as `hardhat/`; EVM contracts live in `crypto/hardhat/`.
- When drafting posts for the user, assume there is no character limit unless the user explicitly sets one.

### Native App Shells — `frontend/desktop/`, `frontend/mobile/`

Both render the live site (`CYBERIA_APP_URL`, default `https://cyberia.church`) instead of bundling it, so a production deploy updates both apps. Both are the Cyberia **wallet** first: they launch on `CYBERIA_APP_PATH` (default `/wallet`), which renders without site chrome (`layouts/WalletFrameLayout.vue` — `app.ts` picks it for the wallet in every container now, a browser tab included), with the rest of the site one link away. The masthead is shell-only: it is the frameless window's title bar and drag region, and in a browser the same link out lives on the wallet's Settings screen. `CYBERIA_APP_PATH` must be a same-origin absolute path — a full URL or `//host` falls back to `/wallet`. Per-directory `README.md` files are authoritative.

The desktop window is fully frameless: one `BaseWindow`, one site `WebContentsView`, no system decoration and no substitute title/menu strip. The wallet masthead is the desktop drag region and its controls opt out with `-webkit-app-region: no-drag`. There is no application menu in this mode, so `commandForInput` answers useful accelerators by physical key. `BaseWindow` has no web contents, so menu roles reaching for a focused `BrowserWindow` are dead — every page command is a `click` on the site's contents — and nothing has keyboard focus until the shell focuses the page. `--native-frame` restores desktop decorations as a compatibility escape hatch.

The desktop shell is the exception to "shells add nothing": it hosts a real BitTorrent client (`src/torrent-engine.js` in a `utilityProcess`, `src/torrent.js`, `src/torrent-rules.js`, exposed as `window.cyberiaNative.torrent`), because the mainline DHT is UDP and peers are TCP and no web view can be one. It opens no socket before a native consent dialog, writes only to `<Downloads>/Cyberia`, hands the page one finished file under 10 MB for pinning, and needs `asarUnpack` since WebTorrent is ESM with a top-level await.

### Browser Extension — `frontend/extension/`

`frontend/extension/README.md` is authoritative. Unlike the shells this one bundles a wallet: an MV3 background holding an AES-GCM/PBKDF2 vault in the same format as `lib/wallet/vault.ts`, EVM accounts on `m/44'/60'/0'/0/{index}` (so the site's phrase derives the same accounts), and an EIP-1193 + EIP-6963 provider injected **only** into granted origins — there is no `<all_urls>` content script, and `scripting.registerContentScripts` is re-synced from the grants. Every signing method stops at a human in a separate approval window; `PASSTHROUGH_METHODS` is the complete list of calls that reach the chain unattended.

**Two engines, one source** (`manifest.mjs` + an esbuild `define`): Chromium gets a service worker and `chrome.*`, Firefox 128+ an ES-module event page, `browser.*` and a gecko id. The relay follows what each engine can honestly do — per-request on Firefox (`proxy.onRequest`, wallet traffic only), browser-wide on Chromium (`proxy.settings`) — and the popup says which. `proxy`/`privacy` are optional permissions asked for in a click; on Firefox `host_permissions` are opt-in too, so the popup offers a one-click grant.

## Architecture Notes

- Laravel bridge logic is under `backend/laravel/app/Services/BridgeService.php`, `BridgeRelayerService.php`, `BridgeFeeService.php`, and `ProcessBridgeRequest.php`.
- **Bridge admission control** (`BridgeAdmissionService`, `BridgeInventoryService`, `App\Support\BridgeCapacity`, table `bridge_reservations`, `POST /bridge/reserve`, `bridge:release-reservations`, `config/bridge.php` → `inventory` + `relay`): the invariant is that confirmed obligations plus active reservations never exceed the destination inventory that is actually deliverable, and that nothing irreversible starts when that number is unknown. Capacity is a **four-state** value and never a bare `null` — `unlimited` (the relayer really mints there), `available` (a finite amount, held as a RAW integer in the destination's own decimals; every comparison is bcmath, never a float, and equality passes), `unmeasured` (manual reserves this server does not read: Yenten/BTC/LTC/XMR) and `unavailable`, which **fails closed** and covers nothing; a balance that cannot pay for its own transaction (ERC20 with no gas coin, SPL on a lamport-less hot wallet) reports zero rather than its face value. A UI check is not the gate: the official flow **claims** capacity at `/bridge/reserve` under a lock over the destination pool *before the wallet opens*, and `/bridge/submit` consumes that reference once — it can refuse nothing, because by then the source transfer is signed, so an unreserved or mismatched submit becomes an obligation of its own instead. The relay order is now **capacity (locked) → payout → durable hash → confirm → burn**: a hash is written the instant a relay script prints it (every script prints `broadcastTxHash` before waiting on a receipt), `hasPayout()` makes a second payout unreachable by any path including `bridge:relay --force`, a delivered payout whose burn failed is `burn_pending` and a retry burns only, and a verified deposit the destination cannot cover is `awaiting_liquidity` — recoverable, nothing burned, obligation on the books. The queue is part of the invariant: slowest relay script < job timeout < connection `retry_after`, pinned by `BridgeQueueSafetyTest`. `CYBER.sol`'s `redeemCyberSol()` burns in the *user's own* transaction, so the reservation is all a server can do there; absolute protection needs a contract-level signed reservation (nonce + expiry) or an escrow model, and is deliberately not built.
- **The Monero corridor is a wallet, not an API key** (`xmr_to_evm` / `evm_to_xmr`, `App\Services\Monero\MoneroWalletRpc`, `BridgeDepositWatcher`, `BridgeDepositCredit`, `bridge:sweep-deposits` every two minutes, column `bridge_requests.deposit_index`, `services/monero/`, tests `MoneroWalletRpcTest` + `BridgeMoneroCorridorTest`): every other chain here can be read by asking somebody else — an explorer, a public RPC, an indexer — and Monero cannot, because an address discloses nothing without its view key. So this corridor exists only where the server holds a `monero-wallet-rpc`, and with none attached **both routes disappear from the bridge entirely** (`routeOperational`) rather than accepting deposits nobody could see. Bridging **in** is address-bound like Yenten: `/bridge/prepare` asks the wallet for a **subaddress** per request — not an integrated address, because a payment id is something the *sender's* wallet must carry and a sender who drops it produces a deposit nobody can attribute — and whatever lands on it is the amount, so there is no hash and no figure taken from the user. Ten confirmations is twenty minutes, which is why crediting moved out of the claim endpoint into `BridgeDepositCredit` and is swept on a schedule: the page checks while it is open and the bridge keeps checking after it closes, through the same code. Bridging **out** sends real XMR from that wallet, and the one way it could double-pay is a `transfer` whose HTTP answer was lost — so `payout_broadcast_at` is stamped *before* the call as the durable record that an attempt began, and a retry asks the wallet what it already sent (by the `bridge:<id>` note it stamps on its own payouts, and by destination-and-exact-amount only for a request whose attempt is already on the row, since two requests paying the same person the same amount are indistinguishable). Monero charges its fee to the *sender* on top of the amount, so the recipient gets the net figure exactly and two separate numbers pay for it: `monero_payout_fee_xmr` withheld upstream and `monero_fee_reserve_xmr` kept back from capacity. Capacity is the wallet's **unlocked** balance (an output is locked ten blocks) and this is the first chain to move out of `unmeasured` by attaching something readable — with no wallet it reports `unmeasured` exactly as before, which is not the same as zero. The in-app wallet needs no special case for `evm_to_xmr` (the source leg is an ordinary ERC-20 transfer, and the recipient defaults to the user's own derived XMR address) and honestly refuses `xmr_to_evm` as `sourceUnsupported`, because it can receive Monero but not spend it.
- Web3 auth uses EVM and Solana nonce flows backed by `WalletNonce` and Sanctum.
- Laravel frontend wallet/bridge composables live under `backend/laravel/resources/js/composables/`.
- EVM contracts include bridge (`CyberBridge.sol`, `WrappedCyberSol.sol`), tokens (`USDC.sol`, `USDT.sol`, `BTC.sol`, `LTC.sol`, `SOL.sol`, `RUB.sol`, `GOLD.sol`, etc.), DAO (`contracts/dao/`), lending (`contracts/lending/`), launchpad/NFT, and QuickSwap forks.
- Anchor bridge instructions live in `crypto/anchor/programs/anchor/src/instructions/`.
- Prediction markets (`/predictions`, `PredictionMarket.sol` at `0xb88063Cb2db16473Fb6deB71BaE364aFd09fdE54`, `App\Services\Predictions\*`, `config/predictions.php`, `predictions:resolve` every five minutes): parimutuel YES/NO in native CYBER, where the only hard part is that someone has to answer the question. The contract gives its oracle 30 days after close and then disables resolution permanently — the first two markets died exactly that way — so a question is written to answer itself where it can. `resources/js/lib/predictions.ts` and `PredictionQuestion.php` are byte-identical mirrors of one format: prose plus a trailing `[px:SOL>80@coingecko]` tag naming asset, direction, threshold and feed. Tagged markets settle from the first quote read after close (strict comparison — landing on the threshold resolves NO); untagged ones are free-form, are reported to Telegram daily via `TelegramOpsNotifier`, and are cancelled (full refunds, no fee) a few days before the refund window would strand them. `plan()` is pure and takes its clock as an argument, so every branch that moves money is tested without a chain; signing is the only step that leaves PHP, and it goes through the relayer key exactly like `ProfileOnchainService`.
- Wallet Settings (`components/wallet/WalletPreferences.vue`, portfolio → Настройки): appearance (theme, language) and alerts (notifications, sounds, desktop startup), plus the one link back to the site. Theme lived on the context bar and language on the masthead until the arithmetic beat both: on a 393px phone the account chip, the network chip and Refresh fill the row, so a fourth control wrapped it onto a second one — thirty-four pixels of button costing fifty-four of height above the fold, on every screen. Both are drawn as the whole choice rather than as a cycle.
- Interface language (`composables/useLocale.ts`, dictionaries in `lib/{wallet,download,progress,console}Messages.ts`): English, Russian and Simplified Chinese, chosen in the browser and never by Laravel — one shared reactive `locale`, kept in localStorage, guessed from `navigator.language` (every `zh-*` lands on Simplified), and written onto `<html lang>` as a full BCP-47 tag, because a browser given a bare `zh` can draw unified Han characters with Japanese glyph shapes. Only `en` is mandatory in a dictionary and `t()` falls back to it, which is why the operator-facing console stays en/ru while the user-facing surfaces carry all three; a page's one-button switch cycles only what its own dictionary has, and the site-wide picker in `WalletMenu.vue` lists everything. Quest titles ship from `config/gamification.php` in the same three languages. `tests/Frontend/LocaleMessagesTest.mjs` pins key sets and `{placeholders}` across languages — a missing key renders in English and is otherwise invisible.
- The operator console ("Пульт", `/crm`, `docs/console.md`, `App\Services\Console\*`, `ConsoleController` + `ConsoleNumbersController`, layout `layouts/ConsoleLayout.vue`, styles `resources/css/console.css`, dictionary `lib/consoleMessages.ts`, table `console_snoozes`): five pages with the same anatomy (tiles + filters + table) became five *lenses* on one stream — Сейчас, Люди, Задачи, Числа, Машины. The home is a **queue**, not a list, because there are three operators who come in between other work and the question they arrive with is "what requires me now": an incident, an overdue promise, a whale's first trade, a falling D7 and an emptying gas tank stand in one line ordered by severity, then by the freshest state change. Every row carries **time-in-state** in the left column (that column is the priority — twelve minutes and three hours look identical on a status board), one obvious action, and a way to put it down until nine in the morning (`Snooze`, `console_snoozes`; a snoozed row stays visible in the watch list with its wake-up time, because a console where "later" means "gone" is not trusted twice). **Silence is a designed state**: an empty queue prints how long it has been quiet, when the last sweep ran and how many services answered it, or it is indistinguishable from a broken collector. Filters became **segments** — a saved question with its rule on screen (`PeopleLens`), and the middle of a person's row is what happened to them rather than their columns. **Люди is also where a person is written down.** Everything else on that lens is derived by the sync, so the two facts with no source are typed on the screen that shows them: a composer on the lens itself (`POST /crm/people`) that stays open, keeps the previous person's type and status and returns to the list rather than to the new dossier — fifteen accounts found in one afternoon are fifteen entries, and a contact created a second ago is already the top row — and, on the dossier, the "Кто это" panel opening in place (`PUT /crm/{contact}`) because half a dossier is a log and the other half is what somebody told us, which ages. The **Подгрузить** button (`POST /crm/sync`) prints the age of what it refreshed underneath it, out of a row per run in `crm_syncs` — `crm_contacts.last_synced_at` cannot answer that question, since the half-hourly balance refresh stamps it per contact — and that row also carries whether the run was **complete**, because the holder scan answers a rate-limit with an empty result rather than an error and a fresh date over a run that read nothing is the lie a freshness date exists to prevent. **Selling is a state, not a deletion**: the run compares the holder set against everybody seen holding and writes the difference down as type `lead`, status `sold`, balance zeroed (segment "Продали, но остались"), never a delete — guarded by doing nothing on an empty scan, touching only contacts with a recorded balance above zero, and never overwriting an operator's `lost`. `x_handle` is a column beside `telegram`: an address is not somebody you can write to, and most people found by looking are found on X. Both are stored **bare** and `App\Support\Handles` collapses the `@name`/URL spellings on the way in (nobody transcribes a handle out of a profile they are looking at) and decides on the way out whether a stored value can be a link at all — the whale sync files numeric Telegram *ids* in that column, so a row whose one action would be `t.me/819…` offers "В досье" instead. Colour is spent only on anomaly: four signals (red down/overdue, amber degrading/running out, magenta person-and-money, cyan action) and hatching for "no data", which never looks like a state and never enters the arithmetic. The banner, the rail badge and the list are one cached build, so they cannot disagree. **Чат** (`/crm/chat`, `Console\ChatRoom` + `Console\LainOsRoom`, `ConsoleChatController`, pages `crm/Chat.vue` and `crm/ChatFiles.vue`, tables `crm_chat_{messages,files,reads}`, `crm:chat-prune` daily) is the sixth lens and the file dump at once: the ask was a place to drop files plus a chat between the operators, and a file here cannot exist without the message that brought it, so it always carries who brought it and what for — `/crm/chat/files` is that same stream read as segments, and its last column is the sentence the file arrived with. One room and no channels (there are three operators; what separates conversations is the object a line names, `#name` resolved through the same `TaskLine` grammar as the task composer); the left column is **time of day** rather than time-in-state, because a room is a log and a log's spine is when; and the one action on a line is **В задачу**, since a pinned message is one nobody does while a task with an owner and a date is one somebody does. LainOS answers only when called by name — `@lainos`, never `@lain`, which is an operator — and the two correspondents behind that name are never blurred: the daemon (`services/lainos`, `POST /chat` on the host's loopback, `LAINOS_HTTP_URL`) has tools and can go and look, the persona (`LainChatService`) can only reason about what it was handed, every answer is stamped with which one gave it and with what it was allowed to see (the console's own **state of the project** — `Console\ConsoleBriefing`, `CRM_CHAT_LAINOS_BRIEFING`: the queue, the machines, the chain with head/lag/prices/pool snapshot/gas tank, the bridge ledger, the thirty-day tiles and the board, out of the caches the lenses already render, dated, and with anything unreadable said rather than zeroed — plus the last N lines, the names and sizes of their files, and a file's text only when it is attached to the calling line; the daemon is told the briefing is a starting point for its own tools and the persona that it is the end of the line, because telling both of them "this is all you have" made the one that can go and look behave like the one that cannot), and an unreachable LainOS is a hatched row with a retry rather than a sentence nobody stands behind. The call runs in a request of its own behind a cache lock rather than on the queue, because this host is not guaranteed a worker and an answer that silently never arrives is worse than one an operator can press again. Files go to the **private** disk and come back only through `/crm/chat/files/{file}` inside the console gate — executables refused by extension, a size cap, and a message and its bytes pruned together, because a file whose reason was deleted is the orphan this design exists to avoid. **Nobody presses F5**: the shell holds one heartbeat for the whole console (`GET /crm/pulse`, `ConsolePulse`, `composables/useConsolePulse.ts`) — every five seconds while the tab is visible, paused while it is hidden and beaten once the moment it comes back — and what comes back is an opaque **version per lens** plus the rail's counts, so the lens whose version moved re-reads only its own props (`useConsoleLive`) and a half-written line in a composer survives. A poll and deliberately not a socket: a push needs a process nobody watches on the host whose scheduler was dormant for months, and this fails out loud instead — three failed beats and the top bar says «не обновляется». A version is a count plus the newest `updated_at` (an edit leaves the count alone, a delete leaves the high-water mark alone), and Сейчас stamps the *material* under its cached queue rather than rebuilding it to ask; `attention` is read from the warm cache only and is `null`, never 0, when it is cold. The room is the exception — these columns keep whole seconds, so it asks its own question every beat (`GET /crm/chat/since`) and gets lines **said**, lines **changed** under the reader and lines **taken back**, against the window it actually holds, with `>=` on the boundary second so a change made in the second of the last read repeats once instead of vanishing. Presence is stamped only for whoever has `/crm/chat` on screen and is sent **with its UTC offset** — a bare `Y-m-d H:i:s` is read by a browser as local time, which drew somebody typing right then as last seen three hours ago. **Finding one person is not reading a segment**: a narrow strip over the table (type, status, search, order — all in the address, so the back button undoes a filter) answers the other task, because `updated_at` on this lens is really the half-hourly balance refresh talking and a lead entered by hand yesterday was not merely far down the list but outside the candidates the lens reads at all — so the default order now pulls in the recently written down explicitly, `sort=added` asks outright, and the search reads `@name` and a pasted profile URL as the bare handle they are stored as (`Handles::searchable`, tags included). **A dossier answers where the conversation stands** (`crm_messages`, `CrmMessageController`, `POST /crm/{contact}/messages`, `DELETE /crm/messages/{message}`, `components/console/CopyValue.vue`): the correspondence is a table and not notes with a convention, because only `direction` makes "we wrote four days ago and they have not answered" a fact the console can state, and `sent_at` is when it was *said* rather than when it was typed in — these lines are entered after the fact, and Telegram/Discord will later import into the same rows behind a per-channel unique `external_id` (null for anything hand-written, which is why repeated nulls in that index are the wanted behaviour). It records and never sends: nothing on this host holds an operator's Telegram session, so "Написать" stays a link out to where the conversation actually happens. "Отвечает" is the **median** gap measured from the *first* unanswered line we sent (the mean turns one three-day reply among sixteen fast ones into a day and a half; the last-line reading forgives a nudge), and a conversation nobody has answered says so instead of showing 0 — while four days of our own silence outranks a whale's balance in the sentence at the top. The stream reads three ways (`?events=all|touch|money`, in the address like every other filter) and is filtered **on the server**, because a page hiding rows out of the newest sixty means "the money inside the last sixty events"; every count under the table is a `count()` of the record and never of the slice on screen. Every shortened value carries a copy button that copies the full string and confirms in place, "+ Задача" takes the board's own `@who !when` grammar minus the part that names the person, and "Что дальше" lists only what is still owed, with the one action that empties it. Old addresses (`/crm/analytics`, `/crm/product`, `/crm/services`, `/crm/product/users/{id}`) redirect to the lens that answers the same question. - Swapping and wrapping in the wallet (`components/wallet/WalletSwap.vue`, `lib/wallet/{swap,wrap}.ts`, reached as an overlay from the portfolio, the network screen, a token and a launch): one screen, two acts that are never blurred. A **swap** is exact-input through the QuickSwap fork named in `lib/liquidityChains.ts` — the same registry `/swap` and `/liquidity` use, which now also carries each chain's routing `hubs`, so wallet and site route through identical assets. What the user agreed to travels into the transaction as a **floor** (`applySlippage`, default 0.5%) instead of being re-quoted after the hold, and price impact is a probe of the same path (the 0.3%/hop fee cancels out of the ratio). Allowances are for **exactly** the trade's amount, never `MaxUint256` — cost included in the quoted fee, with the extra zeroing transaction USDT-style tokens force — and the gas the fee promises is capped at `SWAP_GAS_CAP`. The screen also carries **the pair's own strip** (the quote's route resolved through `lib/wallet/marketHistory.ts` and replayed from the pools' `Sync` events, keyed on the quote's `path`, loaded after the quote and absent when the pools never traded), the routes this one **beat** (`SwapQuote.alternatives` — the search priced every candidate and used to discard the losers), and one line saying what the trade pays on Daily. - Cyberia V3 in the browser (`lib/dexV3.ts`, registered per chain as `liquidityChains.ts` → `v3`, pinned in `tests/Frontend/DexV3Test.mjs`): v2 and v3 both hold real liquidity on the same chain, so `/swap` asks both and takes the better answer rather than sending every trade to the older venue. Three things are load-bearing. A pool's address is **derived**, not looked up — CREATE2 over the *pool deployer* (Pancake splits deployer from factory) and `abi.encode(token0, token1, fee)`, against `POOL_INIT_CODE_HASH`; a stale hash addresses a plausible contract that is not there, so the constant is pinned to an address the contracts themselves derived on chain. - **Tokenised stocks on Robinhood Chain** (`resources/js/lib/robinhoodStocks.ts` + `config/robinhood.php`, both generated by `backend/laravel/scripts/robinhood-stocks.mjs`; `App\Services\RobinhoodStockService`, `Api\WalletStocksController`, `GET /api/wallet/stocks`, wallet screen `components/wallet/WalletStocks.vue` + `lib/wallet/stocks.ts`, icons in `public/token-icons/stocks/`, landing section `#stocks`, pinned by `tests/Frontend/RobinhoodStocksTest.mjs` + `tests/Feature/RobinhoodStocksTest.php`): fifty-three shares and funds — NVDA, TSLA, SPCX, SPY, GLD — held by a broker and represented by ERC-20s on chain 4663, listed in the wallet, tradable on `/swap`, and shown live on the landing page. Icons are vendored rather than hot-linked (fifty-three images from a third party is fifty-three requests telling it what somebody holds), fetched by **ISIN** rather than ticker, and eight of them are PNGs — the generator reads the format off the bytes and writes the extension into the registry, because a PNG served as `image/svg+xml` draws nothing.
- **Liquidity in the v3 pools** (`/liquidity` → «V3 ranges», `lib/dexV3Positions.ts`, `components/dex/V3Liquidity.vue`, pinned in `tests/Frontend/DexV3LiquidityTest.mjs`): the two venues sit on one page as a **switch** and not as a migration — both hold real liquidity and neither is being retired. A v2 position is a balance; a v3 position is an NFT holding a price range, so the screen is ordered by what decides what: the tier decides the tick spacing, the range decides the ratio of the two amounts, and the second amount is therefore derived and never typed (`pairedAmount`, `null` where the price is past the range and the deposit is one-sided). The tick table is `TickMath.sol` ported constant for constant rather than `1.0001 ** tick` in floating point, because the pool decides what a range holds with the integer answer; ticks are then snapped to the tier's spacing and **every price on screen is read back out of the snapped tick**, so what is shown is the position that will exist rather than the number that was typed into it. Withdrawing is two calls in one multicall — `decreaseLiquidity` only *credits* the tokens to the position and `collect` is what pays them out, which is why its ceiling is uint128 max and why the fees come with it — taking the coin back collects into the manager (address zero, its own convention) and unwraps there, and taking all of it out burns the NFT in the same transaction. What is owed is read as `collect.staticCall` from the owner and never off `tokensOwed`, which is only as fresh as the last time the position was touched. The stack redeployed on 2026-09-07 holds **no pools at all**, so adding is also the only way one gets created: `factory.createPool` from the **user's own address** and `pool.initialize` as separate transactions before the mint, never the manager's `createAndInitializePoolIfNecessary` — whoever calls `createPool` is who the factory records as the creator, and that record is the one chance to set what the pool charges. Creating one carries its gas explicitly (it deploys a 23 KB contract by CREATE2), and the price of a pool nobody has traded in is built from two raw amounts rather than from a float, because it is written once and never again.
- Swapping Monero (`config/moneroswap.php`, `App\Services\Monero\MoneroSwapService`, `Api\WalletMoneroSwapController`, `/api/wallet/monero/swap[/quote]`, client `lib/wallet/moneroSwap.ts`): the one asset no aggregator routes and no pool here holds. - Cross-chain swaps (`components/wallet/WalletCrossSwap.vue`, `lib/wallet/crosschain.ts`, `App\Services\CrosschainRouter`, `Api\WalletCrosschainController`, `/api/wallet/crosschain{,/tokens,/quote,/status}`, `config/crosschain.php`, `CROSSCHAIN_FEE_ADDRESS`): the swap screen trades Cyberia's own pools; this one answers "USDC on Base for SOL on Solana", which needs inventory on both sides of every pair, so a router is asked. No key here and nothing signed here: the deposit goes from the user's address to the router's contract. Unset fee address = no fee asked for, said on screen. Pinned in `tests/Frontend/WalletCrosschainTest.mjs` and `tests/Feature/WalletCrosschainTest.php`.
- **Trading on a network Cyberia has no exchange on** (`components/wallet/WalletRouteSwap.vue` inside `WalletSwap.vue`, `lib/wallet/dexscreener.ts`, `lib/wallet/spl.ts`, `routedChainIds()`/`mergeOffers()` in `lib/wallet/crosschain.ts`, `components/wallet/WalletPairChart.vue`, pinned in `tests/Frontend/WalletTokenSearchTest.mjs`): the same router, both legs on one chain, wherever it serves a network this wallet can sign on. Everything else is ordered by **pool depth**, printed on the row with the day's move, because "why these tokens" has to have an answer a person can check. - **The routed fee is taken along the route and has to be claimed** (`CrosschainRouter::appFeeBalance()`, `crosschain:fees --alert` daily, `config/crosschain.php` → `fee.claim_alert_usd`): the router takes `fee.bps` out of the *input* on every routed swap — same-chain and cross-chain, Solana included — so there is no leg of ours in the path and no key of ours near it. What that costs is visibility: the money lands in no wallet and accrues per nothing. - Sponsored fees on Cyberia (`crypto/hardhat/contracts/CyberiaGasStation.sol`, `App\Services\GasSponsorService`, `Api\WalletGasController`, routes `/api/wallet/gas{,/claim}`, `config/wallet.php` `sponsor`, `lib/wallet/gas.ts`, `components/wallet/GasSponsor.vue`, table `gas_sponsorships`, command `gas:station`): a fee is payable only in the coin the chain runs on, so an address holding USDC and no CYBER cannot move its USDC — the state the send screen already names as its own. The station hands that address a fixed drip of CYBER and the user then signs their own transaction *unchanged*, which is the entire reason one mechanism covers sends, token transfers, swaps, mints and everything not yet built: no forwarder, no smart account, no meta-transaction, nothing touching a signing path that tests pin. The two halves are deliberate. The contract enforces **how much at most** — fixed drip, balance ceiling, per-address cooldown, daily cap, pause, operator allowlist — so those bounds hold against anything on this server, a stolen sponsor key included; Laravel decides **who**, which is a question about the world: the address must already own something on Cyberia (Blockscout `tokenlist`, so a bot would have to fund every sybil address with assets worth more than the drip) or have signed into the site, plus per-IP and global daily quotas counted from rows rather than the cache. Both refuse in one vocabulary (`hasGas`, `holdsNothing`, `coolingDown`, `dailyCap`, `empty`, `quota`, `unreadable`) that the browser renders in en/ru/zh. Unsigned on purpose: a drip can only ever arrive at the address named in the request, so a signature would prove possession of a key anyone can generate for free. `GAS_SPONSOR_PRIVATE_KEY` is dedicated and must never fall back to the bridge relayer, whose transactions already lose nonce races, and it pays the gas that *delivers* each drip — so `gas:station --alert` (hourly) watches the tank **and** that key, and an unreadable station is reported as an RPC problem rather than as an empty tank. Cyberia only, permanently: sponsoring BNB or Base would mean buying ETH for strangers. Paying a contract in the coin is itself a contract call, so `nativeSendGas()` reads `eth_getCode` on the recipient and states 120000 (`EVM_CONTRACT_SEND_GAS_CAP`) instead of 21000, and the quote is keyed on that answer — **never estimate a native transfer on Cyberia**: the node answers `eth_estimateGas` for a value transfer with 21000 whether or not the recipient has code, which is how the station's first funding attempt reverted out of gas at 22491 and kept the fee.
- `$LAIN` holders' room in the wallet (`components/wallet/WalletLain.vue`, `Api\WalletLainController`, routes `/api/wallet/lain/{nonce,verify,chat}`, prompt in `LainChatService::replyForHolder`): a chat with Lain gated on holding ≥ `services.lain.minimum_share_bps` (10%) of the live `$LAIN` supply. - Inference API (`/api/ai/v1`, `config/ai.php`, `App\Services\Ai\*`, `App\Http\Controllers\Api\Ai\*`, `docs/ai-api.md`): OpenAI-compatible chat completions — including `stream: true` — in front of the provider credentials already on this host. The registry mirrors free-claude-code's 49 OpenAI-compatible upstreams; provider quirks stay declarative in `config/ai.php`, credentials never leave the server, and local endpoints require an explicit enable flag. A gateway, not a proxy: the catalogue is an allowlist of Cyberia ids mapped to provider + upstream model, so an unknown id is a 400 rather than a bill, a model whose provider is unconfigured leaves `/v1/models`, and a rate-limited or dead model falls back once to the model it names — reported as `served_by`, never after a stream's first byte. Listing/revoking need the signature but not the holding; `ai:key issue … --service` mints gate-exempt keys for Cyberia's own daemons. Per-key quotas live in `AiUsageMeter` (minute in the rate limiter, day in the log so a cache flush cannot reset it), `max_tokens` is clamped not refused, and `ai_api_requests` stores metering with no column a prompt could go in (`ai:prune-usage`, 90 days). Errors use OpenAI's envelope; an upstream 401 becomes a 502, since the rejected credential is ours. **Access has a second door** (`config/x402.php`, `App\Services\X402\*`, `X402Paywall`, `x402_payments`, `x402:check`, `docs/ai-api.md`): x402 over HTTP, for a caller who holds nothing and has no account — an unpaid call is answered `402` with the terms base64'd into `PAYMENT-REQUIRED`, a call carrying `PAYMENT-SIGNATURE` is verified with a facilitator before the work and settled after it, and the transaction comes back in `PAYMENT-RESPONSE`. This host holds no wallet and signs nothing: settlement is the facilitator's job, which is why accepting USDC on Base costs no key, no RPC and no nonce here — and why the facilitator is chosen rather than implied (the default one serves Base *Sepolia* only, which `x402:check` catches instead of an uncollected payment). Order is the design — verification is free and precedes the work, settlement follows it but precedes the first byte (a stream has already pulled its first chunk by then), so a failed answer is never charged and an unsettled payment is never served. The requirements sent to the facilitator are always rebuilt from config, never read back from the payload, since a payer's copy of the terms is a payer's opinion. Prices are flat per call because `exact` charges before the token count exists; metering to actual usage is the `upto` scheme's job and is deliberately absent. The two doors never overlap: a key skips the paywall, a payment skips the key and the holding, and the metering row names whichever one paid.

- Anchor: `cd crypto/anchor && anchor test` or at least `anchor build`
- NO CARRIER: `cd game/nocarrier && godot4 --headless --import . && godot4 --headless --path . -s tests/smoke.gd`
- Jekyll: `cd frontend/jekyll && bundle exec jekyll build`
- Static landing: inspect HTML and validate if a validator is available
- Blockscout compose/proxy: `cd services/blockscout/docker-compose && docker compose config`
- Monero bridge wallet: `cd services/monero && docker compose config` (the corridor itself is covered by `MoneroWalletRpcTest` + `BridgeMoneroCorridorTest`)
- Host heartbeat script: `bash -n scripts/ops/heartbeat.sh`, then `OPS_HEARTBEAT_PRINT=1 OPS_HEARTBEAT_TOKEN=x ENV_FILE=/dev/null bash scripts/ops/heartbeat.sh | python3 -m json.tool` — it builds JSON by hand, so a malformed field is only visible in the payload
